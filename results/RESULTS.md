# Results

Generated by `go run ./cmd/bench -lib <libraries>` from `results/data/*.jsonl`: the latest record per app, form and library. Times are ns per record; code is KB. Each architecture ends with a summary per library against the XOR-BID baseline. [DECIMAL64.md](DECIMAL64.md) sets `decimal64` beside the `decimal128` libraries of the same toolchains.

- **code** is the size of the program's own machine code in KB: its main package and this repository's packages, where the library's operations are compiled and, for the built-in decimal types, inlined. The library's own code, the runtime and the standard library are left out. It is the instruction bytes `go tool objdump` lists, without padding between functions.
- **compute** is the program's own timed loop (arithmetic and in-memory formatting of the output; no file I/O, no input decoding). It is the fastest sample over 3 processes, and the ranking key.
- **median** and **p10–p90** cover the second half of each process's samples (the first half counts as warm-up). A wide range means the value is not stable.
- **xcheck** is the runner's own clock divided by **compute**: it times a run with twice the samples and divides the extra wall time by the extra passes. Near 1.00 means the program's timer agrees; ⚠ marks a ratio outside 0.90–1.25 (banking 0.90–2.50, because it rebuilds its accounts between passes outside the timed loop).
- **whole** is one gated run from process start to exit, fastest of N, after one untimed warm-up run (a newly built program's first launch is much slower). **startup** is a do-nothing Go program launched the same way, between the whole runs, so whole − startup is the program's own work.
- **correct**: ✓ = every gated run matched the golden byte for byte; *n*/*m* = output files matched (risk); ✗ = a mismatch in at least one run.

Libraries:

- **go-builtin-decimal128-ubd-level3**: The ubd128 fork at -d=ubdlevel=3: level 2's inline paths, then the kernel's own first paths promoted inline behind them (since the fork's 0493529123; at 447e9c0b4e and before, level 3 was the inline paths derived from the BID lowering, and level -1 before 45ff73c327); the most UBD code.
- **go-builtin-decimal128**: The built-in decimal128 of the ubd128 fork, stored as UBD, at its default -d=ubdlevel=2: small narrowed inline paths for +, -, *, the comparisons and the tests against zero, every other operation a kernel call.
- **go-builtin-decimal128-ubd-level1**: The ubd128 fork at -d=ubdlevel=1: every decimal128 operation a kernel call, nothing inline; the smallest code.
- **go-builtin-decimal64**: The built-in decimal64 of the ubd128 fork (stored as XOR-BID64), the same toolchain as go-builtin-decimal128: the apps at 16 digits on the suite's 64-bit BID inputs, gated against its 64-bit goldens or, where the output is the same, the 128-bit ones. strconv formats decimal64 by widening it to decimal128, which is part of its time.
- **go-builtin-decimal128-xorbid**: The built-in decimal128 of Marcelo Cantos's Go decimal toolchain, stored as XOR-BID (BID with the high word XORed so that all bits clear is +0): the baseline the UBD builds are compared with.
- **miguel-decimal128-go**: [decimal128-go](https://github.com/migueldecimal128/decimal128-go), pure Go. Two adapter wrappers are real calls: FromBID128 (input decoding only) and quantize with a rounding direction (telco: +0.9% fastest sample, +1.2% median).
- **bid754**: [bid754](https://github.com/sky1core/bid754), a pure-Go port of Intel's libbid v20U4. Its adapter re-lays Intel's string form ("+150E-2") into decNumber's ("1.50"), about 20 ns per string, and reaches its per-direction round-to-integral methods through a table (about 34 ns against 26 ns direct); both are part of its time. It has no power, logarithm or directed quantize, so risk, banking and telco do not run with it.

Workloads:

- **euro_conversion**: 100 records: legacy-currency ↔ euro triangulation; stderr transcript byte-identical to the golden.
- **risk_management**: 20 stocks: per-stock CAPM prediction; **correct** counts the per-stock output files that match the golden.
- **tax_preparation**: 1 return per form (fed / ca / nc); stderr transcript byte-identical to the golden. One return per process, so **whole** is mostly startup.
- **banking**: 643 records: deposits, mortgages, credit cards; stderr transcript (3,326 lines) byte-identical to the golden.
- **telco**: 1,000,000 calls: Mike Cowlishaw's telephone billing run; the 1,000,000-line output matches the reference (SHA-256) and the control totals 1004737.58 / 57628.30 / 25042.17 match his published values. Its timed loop includes decoding each record and formatting each line, as the benchmark defines.

Libraries:

- **go-builtin-decimal128-ubd-level3**: The ubd128 fork at -d=ubdlevel=3: level 2's inline paths, then the kernel's own first paths promoted inline behind them (since the fork's 0493529123; at 447e9c0b4e and before, level 3 was the inline paths derived from the BID lowering, and level -1 before 45ff73c327); the most UBD code.
- **go-builtin-decimal128**: The built-in decimal128 of the ubd128 fork, stored as UBD, at its default -d=ubdlevel=2: small narrowed inline paths for +, -, *, the comparisons and the tests against zero, every other operation a kernel call.
- **go-builtin-decimal128-ubd-level1**: The ubd128 fork at -d=ubdlevel=1: every decimal128 operation a kernel call, nothing inline; the smallest code.
- **go-builtin-decimal64**: The built-in decimal64 of the ubd128 fork (stored as XOR-BID64), the same toolchain as go-builtin-decimal128: the apps at 16 digits on the suite's 64-bit BID inputs, gated against its 64-bit goldens or, where the output is the same, the 128-bit ones. strconv formats decimal64 by widening it to decimal128, which is part of its time.
- **go-builtin-decimal128-xorbid**: The built-in decimal128 of Marcelo Cantos's Go decimal toolchain, stored as XOR-BID (BID with the high word XORed so that all bits clear is +0): the baseline the UBD builds are compared with.
- **miguel-decimal128-go**: [decimal128-go](https://github.com/migueldecimal128/decimal128-go), pure Go. Two adapter wrappers are real calls: FromBID128 (input decoding only) and quantize with a rounding direction (telco: +0.9% fastest sample, +1.2% median).
- **bid754**: [bid754](https://github.com/sky1core/bid754), a pure-Go port of Intel's libbid v20U4. Its adapter re-lays Intel's string form ("+150E-2") into decNumber's ("1.50"), about 20 ns per string, and reaches its per-direction round-to-integral methods through a table (about 34 ns against 26 ns direct); both are part of its time. It has no power, logarithm or directed quantize, so risk, banking and telco do not run with it.

- **risk_management**: 20 stocks: per-stock CAPM prediction; **correct** counts the per-stock output files that match the golden.

- **banking**: 643 records: deposits, mortgages, credit cards; stderr transcript (3,326 lines) byte-identical to the golden.

Its timed loop includes decoding each record and formatting each line, as the benchmark defines.
